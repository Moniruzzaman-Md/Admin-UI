# Hotel Booking Form — dev notes

Page: `booking-form.html` · Live portal: Booking Management (Hotel) › All Booking → **+ Add New** (`/admin/booking-management-hotel/booking-form?returnUrl=…`). Not a sidebar item; the sidebar highlights All Booking.
Scope: whole form (Add and Edit). Header and sidebar are the existing shell, unchanged. Ported from the standalone design `manual-booking-form/output/manual-booking-form.html`, then aligned with the live portal form (2026-11-22).

Prototype only (not part of the design): the dashed **Open edit sample / Open Add form** link switches between the Add form and Edit for the newest saved booking (`booking-form.html?mode=edit`). All Booking › Edit opens a saved booking (`booking-form.html?id=…`). Save with no errors stores the booking in the shared booking list (`js/data.js` › `Bookings`) and returns to All Booking; with errors it marks the fields and shows the payload preview. Back (←) returns to `returnUrl` (All Booking).

## Rules

- **Contracting Comment** is a rich-text box: bold, italic, underline, numbered / bullet list (no links, attachments or other tools). Saved as HTML (`contracting_comment: JSON.stringify([html])` as before; `null` when it contains no text). Render it as sanitised HTML wherever it's displayed.
- **Layout.** Booking Source & Pricing → Hotel Details | Contact Details + Contracting → Rooms & Guests → Cancellation Policies → Price Summary → Save.
- **Booking Source & Pricing.** Left = Supplier (Supplier / API, Supplier Currency, Supplier Reference No — required, Conversion Rate / Reverse Rate). **Supplier Currency** is filled in from the chosen supplier and can't be changed ("Comes from the supplier" until a supplier is picked); an offline supplier added from this form gets its currency in the New offline supplier drawer. Right = agent side: **Platform Type** (B2B only; required) → **Agent** (required; list filtered by platform, disabled until a platform is selected, cleared when the platform changes; shows name + ID and searches both; the labels, Price Summary column and agent cancellation-policy group say "Agent") → **Agent Currency** (required; disabled until an agent is picked; the system's currencies (js/data.js); cleared when the agent changes) → **Market** (required; the markets in the chosen client currency in the chosen agent currency, shown `MALAYSIA (MYR)`; disabled until the agent currency is set; cleared when the agent changes or when it doesn't match a new currency). Then **Conversion Rate** “1 USD = [x] MYR” and **Reverse Rate** “1 MYR = [y] USD” (one of them required; > 0, up to 6 decimals; typing either fills the other with `1 ÷ value`, shown to 6 dp; calculations use the conversion rate; disabled until both currencies are set; same currency → both fixed at 1; changing either currency clears both), Markup Type (Percentage / Flat), Markup Rule (required once a type is chosen; % for Percentage, agent currency for Flat). Right pane rows: Platform Type | Agent · Agent Currency | Market · Markup Type | Markup Rule.
- **Meal** (top of Rooms & Guests): searchable list of meal names with their codes (Breakfast BB, Room Only RO, Half Board HB, Full Board FB, All Inclusive AI, … Iftar Or Suhur IOS); search by name or code; shown `Half Board (HB)`; optional. Sent as the meal name in `meal_info.fullMealDetails`.
- **Rooms & Guests.** One room with one guest form is open by default; at least one room. Each room: Room Type (required), Room No (automatic 1, 2, 3… in order, read-only, renumbered when a room is removed), Price (required, **supplier currency**; rooms added after the first are pre-filled with Room 1's type and price, editable), Agent Price (read-only, calculated; a small line above it shows `price × rate = converted + markup`, e.g. `120.00 × 4.6992 = 563.90 + 25.00 (F)`), then its guests. "+ Add Guest" per room; a room's last guest and the last room can't be removed. Each room needs at least one adult.
- **Guest.** Title (Mr / Ms / Mrs, also for children; required; picking it sets Gender — Mr → Male, Ms / Mrs → Female — which stays editable), First / Given Name (required), Last / Surname (required), Type (Adult / Child; default Adult), Age (Child only, 0–12, required; typing above 12 is capped at 12), Gender, Nationality (country list showing the ISO code — list pill and selected value `Bangladesh (BD)`; search by name or exact code). Nationality: choosing or changing it on *any* guest also applies it to every other guest whose nationality is empty or was the same as this guest's previous value; guests set to a different nationality keep theirs. New guests start with the most recently chosen nationality. Changing a guest to Child clears their Lead flag; changing to Adult clears Age.
- **Lead guest.** "Lead guest" tick on adult guests; exactly one across all rooms (ticking one unticks the others). The first guest of Room 1 is ticked by default. Required on save. `lead_pax_name` = lead guest's first + last name (not shown as a field).
- **Contact Details** (booking-level, outside rooms; only these three fields, **all required**): Email (valid format), Country Code (searchable, e.g. "+60 Malaysia"), Mobile Number (digits only, 6–15).
- **Booking Status** (Hotel Details): CONFIRMED, RE CONFIRMED, CANCELLED; disabled until a supplier is picked ("Select supplier first"); cleared when the supplier is cleared.
- **Pricing** (per room, then summed): `converted = round2(room price × rate)`; markup = Percentage → `round2(converted × rule ÷ 100)`, Flat → `rule` per room, none → 0; `agent price = converted + markup`. Totals: Supplier Price = Σ room prices (no separate input), Converted = Σ converted, Markup = Σ markup, Agent Total Price = Σ agent prices. Recalculates on any room price, rate, markup or room count change. Needs both currencies, the rate and every room price.
- **Price Summary** (read-only, bottom): one row per room — Room, Room Type, Guests, Supplier Price, Converted, Markup, Agent Price — and a Total row; above: supplier name, `1 USD = 4.7000 MYR`, markup rule; below: `(USD 240.00 × 4.7000) = MYR 1,128.00 + MYR 50.00 (25.00 × 2 rooms) = MYR 1,178.00`, the flat-markup note, and the Agent Total Price. Missing inputs are listed instead of the calculation.
- **Payload.** `rooms[]`: `room_no` (1-based), `room_type`, `supplier_price` + `supplier_currency`, `converted_price`, `markup_amount`, `price` = agent price, `currency` = agent currency. `guests[]`: `room_no`, `title`, `first_name`, `last_name`, `full_name` (first + last), `type`, `child_age`, `gender`, `nationality`, `nationality_code`, `is_lead`. `lead_pax_name`, `guest_email`, `contact_country_code`, `contact_mobile`, `contact_no` (code + number). `total_price` = Agent Total Price; `original_total_price` = Σ room supplier prices; `price_secret`: `reverseConversionRate`, `supplierPrice` (Σ room supplier prices), `conversionRate`, `convertedPrice`, `markupType`, `markupRule`, `markupAmount`, `noOfRooms`, `portalCurrency` = agent currency, `finalPrice` = total. Add mode also sends `platform_type`, `customer_id`, `supplier_currency`, `customer_currency`, `market_id`, supplier fields below.
- **Supplier / API** list: one group, **Suppliers** (each shown `Name - SHORT CODE`; an offline supplier has no short code, so its name only), holding the active API suppliers and offline suppliers. Offline suppliers show an **Offline** tag in the list and in the field. Its footer **"Other — add offline supplier"** opens the **New offline supplier** drawer — the same drawer, fields and rules as Offline Supplier List › New offline supplier, without the Active switch: Supplier name, Supplier code, Currency (all required), Emails and Phones (any number; at least one email or phone), Hold booking (on/off, no charge). Always created Active. Text typed in the supplier search before opening it is put in Supplier name. **Create supplier** saves it (it shows on Offline Supplier List), adds it to the list and selects it; its currency becomes the Supplier Currency; toast "‹name› added to Offline Supplier List". Cancel / × / Esc closes it without adding anything. Payload: `supplier_type` = `API` / `OFFLINE`, `supplier_id` = the supplier's id (also for one just created).
- **Edit mode** (`unique_trans_id`, shown in the Hotel Details header): Supplier / API, Supplier Currency, Platform Type, Agent, Agent Currency and Market are locked; everything else stays editable.
- Amounts can't be entered before their currency: room prices and supplier cancellation fees ← Supplier Currency; agent cancellation fees ← Agent Currency; Markup Rule ← Markup Type (Flat also agent currency). Clicking a locked field focuses what it waits for. A currency cleared after amounts were entered keeps the amounts but flags them and blocks Save.
- Hotel Country / City: searchable; City disabled until Country, filtered by it, cleared when it no longer matches. Check-out ≥ Check-in (earlier dates disabled); night count shown. Booking Date can't be in the future (later dates/times disabled in the picker; Save also checks it against the current date-time). Star rating 1–5 or empty. Dates display `DD Mon, YYYY` 24-hour; stored `YYYY-MM-DD`, `YYYY-MM-DDTHH:mm`, policy `YYYY-MM-DDTHH:mm:ss`. Amounts: digits + one decimal point, max 2 decimals.
- Cancellation policies: customer and supplier groups side by side; From empty = until the To date, To empty = onwards; a new policy's From is pre-filled with the previous policy's To + 1 second (e.g. To `16 Feb 2027 11:59:58` → From `11:59:59`; empty if the previous policy has no To) and keeps following that To until the user changes the From; **Time Format is one setting for all policies** (top of the card): Local or UTC (exclusive choice, default Local). UTC → sign (− / +), hours (digits, required), minutes (:00 / :30 / :45); hours 0–14 for +, 0–12 for −, and the maximum offsets can't have minutes. Errors show as soon as an invalid value is entered (or on Save if hours are empty). Sent on every policy as `timeFormat` (`Local` / `UTC+5:30` / `UTC-3`) and as `cancellation_time_format`; One policy for all rooms OFF → one set per room, titled "Room {no}: {type}".
- **Cancellation policies wait for the price details** the client policy is calculated from. Until they're set, the auto calculate row (switch, Offset, One policy for all rooms) and all policies are dimmed and can't be used; a line above them names the first missing one and clicking it goes to that field: Select supplier → Select platform type → Select client → Select client currency → Enter conversion rate → Enter markup amount (only when a markup type is picked) → Enter room (N) price (only for a Percent markup; every room). Time format stays usable. If one is cleared later, the section locks again and keeps what was entered.
- **Deadline date & time** (Hotel details) is read-only, worked out from the client cancellation policies — as Hotel_API (`BookCHelper.GetEarliestPaidCancellationDate`): the earliest From of a client policy with a fee above 0, across all rooms. Only free policies → now − the Offset hours (the "now" kept from the first save). No client policy yet → "Waiting for client policy"; a client fee not known yet (e.g. no conversion rate) → "Waiting for client policy fees" (deadline saved empty). Works whether the client policies are auto-calculated or typed. The list's Deadline date column shows the saved value.
- **Policy To can't be before its From** (supplier policies, and client policies while auto calculate is off). The To calendar starts at the From (earlier days greyed out). If the From is later moved past the To, the To keeps its value, gets a red border and "To can't be before From." at once, and blocks Save. The same date and time for both is allowed.
- **Auto calculate client policy** (switch under Time format, on for a new booking; off for bookings saved before it existed, so their typed client policies stay). Same maths as Hotel_API (`APICommonHelper.ConvertCancellationPolicy`, `HotelMapperManager.CalculateCancellationPrice`). On: client policies are read-only, one per supplier policy — **From = supplier From − hours − 1 s (empty supplier From → now − hours; "now" is fixed when the booking is first saved, so reopening it doesn't move it), To = supplier To − hours − 2 s** (**Offset** hours field next to the switch, whole hours 0–720, required while on, prefilled 36); **fee = supplier fee × conversion rate + the markup of the rooms the policy covers** (the same markup amount the room price gets: Percent = % of the converted room price — all rooms for one policy, that room for a per-room policy; Fixed = fixed × rooms covered). A free (0) step gets no markup. Fee waits for the conversion rate (and, for Percent, the room price). Off: the calculated policies stay as an editable start. Auto calculate is the preferred way, so **switching it off asks first** (shared modal, warning): "Turn off auto calculate?" · "Auto calculate is the preferred way. It builds client policies from the supplier's, like API bookings, so the client always cancels before the supplier." · Times: N h before the supplier's · Fees: Supplier fee × rate + markup · note (red) "If off, you enter client policies yourself. They won't update when supplier policies, rate or markup change." Buttons **Keep on** (focused) / **Turn off**; ✕, Esc and the backdrop keep it on. Switching it back on needs no confirmation. Payload: `client_policy_from_supplier`, `client_policy_hours_before`.
- **Remarks (Back office only)**: its own card below Price summary, one optional free-text box. Admin-only note — never shown to the client or sent to the supplier. Saved with the booking and shown again on edit. Payload: `remarks` (null when empty).
